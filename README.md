# RTK Skills — ECI Distribution

Enterprise skills and rules for adopting [RTK (Rust Token Killer)](https://www.rtk-ai.app/) — cuts AI-agent token consumption 60–90% on CLI command output.

RTK version pinned by this toolkit: **0.42.4** (see [`RTK_VERSION`](RTK_VERSION)). Cursor + Claude Code are supported as equal first-class targets.

## Adoption order — audit first

ECI rolls out RTK **audit-first** (we do not force-init the fleet blind). Before rewriting guidance or pushing global init, baseline a few pilot machines so the rollout is evidence-driven.

1. **Audit 5–10 pilot machines** with the `rtk-audit` skill — one comparable report each (hook status, gain, missed savings, session adoption, a single recommended fix).
2. **Fix the common failure** the audits surface (usually: Cursor hook not installed, or the wrong crates.io `rtk` package).
3. **Adopt** via the three-layer path below.
4. **Re-audit** after one agent session — pilots should show non-zero `rtk gain`. Debrief with `/aha` and the audit `return_packet`.

```bash
# Ask the agent on each pilot machine:
"Run the rtk-audit skill and give me the report."
```

## Three-layer adoption

RTK behavior composes in three layers — adopt top-down, each layer is independent:

| Layer | What | Where | Who |
|---|---|---|---|
| **1. Global init** | The pre-tool-use hook that rewrites commands transparently | `rtk init --global` (Claude) / `rtk init -g --agent cursor` (Cursor) | Each developer, once per machine |
| **2. Repo skills/rules** | Behavioral guidance the agent loads in that repo | `.claude/skills/` + `cursor-rtk/.cursor/rules/` committed to the repo | Repo owner commits; every clone gets it |
| **3. Repo filters** | Project-local `.rtk/filters.toml` for this toolchain (niche CLIs, built-in overrides) | `.rtk/filters.toml` committed to the repo | Repo owner authors; run `rtk trust` after cloning |

Layers 2 and 3 travel with the code — that is why ECI prefers repo-scoped skills/rules and committed `.rtk/filters.toml` over machine-only config.

## Quick start

### 1. One-command adoption (engineers)

The fastest path. From your product repo (or pass `--repo <path>`), run the toolkit's bootstrap:

```bash
/path/to/rtk-skills/scripts/adopt.sh
```

One command:
- installs RTK pinned to `RTK_VERSION` (if missing or wrong package)
- inits **both** hooks: `rtk init --global` (Claude Code) + `rtk init -g --agent cursor` (Cursor)
- copies `rtk-adoption` / `rtk-operations` / `rtk-audit` to `~/.claude/skills/` (global)
- seeds your repo: `.cursor/rules`, `.claude/skills`, `.rtk/filters.toml`, and an RTK block in `AGENTS.md` + `CLAUDE.md` (idempotent)
- applies ECI governance (telemetry off, `exclude_commands`, `RTK_TELEMETRY_DISABLED=1`) — add-if-missing, respects existing values
- runs `rtk trust` in your repo (use `--no-trust` to review filters first)
- verifies with `rtk init --show` + `rtk verify` and prints a readiness summary

Then **restart Claude Code and Cursor**, run a few commands, and check `rtk gain` (non-zero = savings flowing).

Flags: `--dry-run` · `--scope global|repo|both` (default `both`) · `--repo <path>` (default `$PWD`) · `--no-trust` · `--yes`.
**Native Windows (PowerShell):** `pwsh ./scripts/adopt.ps1` runs the same seven steps — Windows-zip install with SHA-256 checksum, `%APPDATA%` config, user-PATH + user-env-var governance. Native Windows has no auto-rewrite hook, so agents prefix `rtk` per the committed rules (rules-only mode). WSL2 engineers use `adopt.sh`.

### 2. Validate the package (maintainers)

```bash
./scripts/validate.sh           # structure + artifacts (no RTK needed)
./scripts/check-parity.sh       # Claude skills ↔ Cursor rules agree
./scripts/check-links.sh        # http(s) links resolve
./scripts/validate.sh --full    # also requires RTK installed
```

### 3. Adopt in a product repo (manual, layers 2 + 3)

**Claude Code** — copy skills into the repo:

```bash
cp -R .claude/skills/rtk-adoption .claude/skills/rtk-operations .claude/skills/rtk-audit /path/to/repo/.claude/skills/
```

**Cursor** — copy rules into the repo:

```bash
cp -R cursor-rtk/.cursor /path/to/repo/
```

**Drop-in agent snippets** for product repos' own `AGENTS.md` / `CLAUDE.md`:

```bash
cp examples/snippets/AGENTS.md examples/snippets/CLAUDE.md /path/to/repo/   # then merge in
```

**Repo-level filters** (layer 3):

```bash
mkdir -p /path/to/repo/.rtk && cp examples/filters.toml /path/to/repo/.rtk/filters.toml
# customize for your toolchain, commit, then run `rtk trust` in the repo
```

**Every developer, once per machine** (layer 1) — pick your platform:

| Platform | Install | Init — Claude Code | Init — Cursor | Config path |
| --- | --- | --- | --- | --- |
| **macOS** | `brew install rtk` | `rtk init --global` | `rtk init -g --agent cursor` | `~/Library/Application Support/rtk/config.toml` |
| **Linux / WSL** | [install.sh](https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh) | `rtk init --global` | `rtk init -g --agent cursor` | `~/.config/rtk/config.toml` |
| **Windows (WSL)** — recommended | install.sh inside WSL | `rtk init --global` from WSL | `rtk init -g --agent cursor` from WSL | `~/.config/rtk/config.toml` |
| **Windows (native)** | [GitHub release zip](https://github.com/rtk-ai/rtk/releases) | `rtk init --global` + explicit `rtk` prefixes | `rtk init -g --agent cursor` + explicit `rtk` prefixes | `%APPDATA%\rtk\config.toml` |

To pin the installer to this toolkit's version:

```bash
curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | RTK_VERSION=v0.42.4 sh
```

```bash
# macOS / Linux / WSL
brew install rtk                          # macOS
rtk --version && rtk gain                 # verify correct package (not the crates.io collision)

rtk init --global                         # Claude Code (ECI default)
rtk init -g --agent cursor                # Cursor

# restart your AI tool, then confirm savings are flowing
rtk gain                                  # savings counter should increment
```

```powershell

# 2. rtk --version && rtk gain            # confirm correct package
# 3. rtk init --global                    # Claude Code
#    OR: rtk init -g --agent cursor       # Cursor
# 4. Restart your AI tool

```

### 4. Project-local filters require trust (0.42.x)

After cloning (or committing) a repo with `.rtk/filters.toml`, run **once** in the repo:

## CI

[`.github/workflows/rtk-skills-ci.yml`](.github/workflows/rtk-skills-ci.yml) has two jobs:

- **`package`** (every push/PR, no RTK) — `validate.sh` + `check-parity.sh` + `check-links.sh`. Never requires `rtk gain`, so it passes on a clean runner.
- **`full`** (when `RTK_VERSION` changes, or `workflow_dispatch`) — installs the pinned RTK via `install.sh`, installs the hook, runs `rtk verify`, then `validate.sh --full`.

Bump [`RTK_VERSION`](RTK_VERSION) to trigger a full validation run against the new release.

When RTK behavior changes, update all of these together:

1. `.claude/skills/rtk-adoption/SKILL.md`, `rtk-operations/SKILL.md`, `rtk-audit/SKILL.md`
2. `cursor-rtk/.cursor/rules/rtk.mdc` and `rtk-operations.mdc`
3. `RTK_VERSION` + the filter schema in `examples/filters.toml` / `.rtk/filters.toml`
4. RTK Enterprise Adoption Guide (external)

```bash
./scripts/validate.sh        # structure + artifacts

./scripts/check-links.sh     # links
./scripts/pack-skills.sh     # rebuild dist/
```

## Troubleshooting

See the `rtk-operations` skill/rule. Common issues:

- **Skills not loading** — ensure files are named `SKILL.md` (uppercase), not ZIP archives named `skill.md`.
- **No token savings** — RTK hook not installed; run `rtk init -g --agent cursor` (Cursor) or `rtk init --global` (Claude Code) and restart the tool. Run the `rtk-audit` skill to pinpoint.
- **Project filters not applying** — run `rtk trust` in the repo after cloning (0.42.x security gate).
- **Read/Grep/Glob output not filtered** — expected: the hook covers shell/Bash only. Prefer shell `rg`/`cat`/`find` or `rtk read`/`rtk grep`/`rtk find`.
- **Windows native: no auto-filtering** — expected; use WSL for full hooks, or ensure `rtk.mdc` rules are committed and the agent prefixes `rtk`.
- **Wrong `rtk` package** — `rtk gain` fails; uninstall the crates.io "Rust Type Kit" and reinstall from Homebrew or GitHub releases.
